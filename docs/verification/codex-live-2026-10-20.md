# Live Codex runs, 2026-10-20

Seven short `codex exec` runs, to see whether the Codex build behaves in a real model session the way the generator and the validator assume.
This is a record of what happened, not a benchmark: one plugin, one tiny repository, one model, one run each.

## Setup

- Codex CLI 0.162.1, model `gpt-6.1-sol`, reasoning effort low, the author's ChatGPT login.
- An isolated `CODEX_HOME` in a temporary folder holding a copy of the login file. The copy's `last_refresh` was set to the current time so that Codex would not refresh and rotate the login's refresh token; after the runs the refresh token of the copy was compared with the original (unchanged), and the copy was deleted. No real project and no real Codex settings were touched.
- The plugin came from this repository as a local marketplace: `codex plugin marketplace add <clone>`, `codex plugin add clean-code@guided-plugins`.
- A throwaway git repository with one file, `src/calc.py`:

  ```python
  def f(a, b, flag):
      # TODO fix this later
      if flag:
          return a + b
      return a - b
  ```

- Text of the plugin and of this repository's file went to OpenAI as part of the model requests.
- Usage over the seven runs: about 428,000 input tokens (320,000 of them cached) and about 3,800 output tokens.

## Runs

| # | Command (shortened) | Sandbox | What happened |
| --- | --- | --- | --- |
| 1 | `codex exec "Review src/calc.py for naming problems only. Do not edit anything. Answer in under 100 words."` | read-only | The model said it would use the clean-code naming skill, read `skills/naming/SKILL.md` from the plugin cache with no skill named in the prompt, and reported three naming findings (`f`, `flag`, `a`/`b`). No files changed. Implicit loading of a rule skill works. |
| 2 | `codex exec '$clean-code:review src/calc.py'` | read-only | The manual workflow ran. It read `skills/review/SKILL.md`, `skills/principles/references/mini.md` and four sibling skills (`naming`, `function-contracts`, `comments`, `function-shape`) through the relative paths in the skill, and answered in the review template: three ranked findings (a boolean flag parameter, naming, a TODO), a "Seen nearby", "Checked" and "Not checked" line, and a closing priority. The argument reached the skill. |
| 3 | `codex exec '$clean-code:install-roles Install them for the current project only (.codex/agents in this repository).'` | workspace-write | The model followed the skill and tried to create `.codex/agents`; the sandbox refused (`Read-only file system`; Codex keeps `.codex` read-only inside the workspace). It reported that and changed nothing. This showed a gap in the skill: it did not say what to do when the copy needs approval. |
| 3b | The same prompt after the skill text was changed (the destination is outside the writable area, ask for approval, never work around the sandbox, otherwise print the command) | workspace-write | The model said it could not request approval in `codex exec` and printed the command with the real source and destination paths. Run by hand in the throwaway repository, it installed all 22 role files. |
| 4 | `codex exec "Use the clean-code-naming-reviewer role (a subagent) to review src/calc.py, then give me its verdict in under 60 words."` | read-only | Codex called its `spawn_agent` tool with `agent_type` `clean-code-naming-reviewer`; the session log has a subagent thread whose `agent_role` is that role; the verdict (rename `f`, rename `flag`) came back in the answer. The installed role loaded, was selectable by name and ran. |
| 5 | `codex exec "Use the clean-code-refactorer role (a subagent) to create a file hello.txt containing the word hi ... Tell me ... whether the file was created."` | read-only | No file was created (checked on disk); the subagent reported that the filesystem is read-only. The session sandbox applies to a subagent. The `refactorer` role is an implementer: only the sandbox stopped it. |
| 6 | `codex exec '$clean-code:mode-mentor Rename the function f in src/calc.py to a clearer name.'` | workspace-write | `f` was renamed to `add_or_subtract` (checked with `git diff`). The answer was short, had the mode's **Why** block, marked the name as "my added judgment" as the mode requires, and pointed to `$clean-code:naming`. It did not ask the mode's check question, which the mode skips for trivial answers. |

## What this does not show

- One plugin and one model. The other 13 plugins are generated by the same code and pass the same structural checks, but were not run.
- No measurement of quality. Whether the reviews are good, or better than none, is not tested.
- Run 4 and run 5 show a role being used when asked for by name, which is what the Codex build promises. They do not show Codex choosing a role on its own.
- The `--profile review` form (a `review.config.toml` with `sandbox_mode = "read-only"`) was checked only in the prompt Codex builds, not with a model run.
