# Eval results

Generated by `scripts/summarize-evals.mjs` from `evals/summary/*.json`. Do not edit by hand. How the suites work: [evals/README.md](../evals/README.md).

**What is measured.** Each suite plants several violations of the book's rules in small realistic files and scores a code review by the share of them it finds (one judge-graded criterion per planted violation), plus a clean file where a review should find nothing serious.
Three numbers per fixture: **baseline** (a natural prompt, no plugin), **natural prompt with the plugin installed** (do the plugin's skills fire on their own?) and **the plugin's workflow** (`/<plugin>:review`).

**How much to trust it.** 1 run per case; Claude Code 2.1.308; model: default of the Claude Code session; 2026-10-26, 2026-11-06; about $13.91 of model usage in total.
A single run per case is a smoke test: expect a swing of one planted violation either way, and judge-graded criteria are not perfectly stable. The fixtures were written by the same project that wrote the plugins, and the graders encode the plugins' own idea of a violation, so a high score shows that the plugin does what it says, not that its rules are right. No real project was measured. Treat differences of 15 points or less as noise until a suite has run three or more times.

## Reading the results so far

5 of 14 plugins have results; the others have suites that have not been run (see "How to run").

- **The plugin's own workflow found more of the planted problems than the model alone in 5 of 5 plugins**, by 13 to 68 points on average over the detect fixtures (workflow and baseline are scored on the same graders; the report-format checks are not counted). 2 of those differences are  15 points or less, which one run per case cannot distinguish from noise.
- **The natural prompt with the plugin installed** scored 7 to 43 points above the baseline, although the model called one of the plugin's skills in 0 of 5 plugins. So that difference is either noise (one run per case) or the effect of the plugin's descriptions sitting in the context; these runs cannot tell which. Treat the plugin's skills as something you invoke, not something that fires on its own.
- **Clean control** (code that follows the book; the column shows baseline / natural + plugin / workflow). The workflow scored lower than the natural prompt with the plugin for A Philosophy of Software Design, Designing Data-Intensive Applications. Read this column as a calibration check, not as a false-alarm rate: the natural prompt says that "nothing needs to change" is an acceptable answer and the slash prompt cannot, the controls are a single fixture each, and a reviewer may legitimately report a real correctness point that the grader reads as a design problem. The baseline itself scored under 75% on the control of Designing Data-Intensive Applications: for those the grader or the fixture needs work before the number means anything.

## How to run

```bash
claude auth login                                   # the runs use your Claude account; a failed login makes every run fail (nothing is recorded then)
node scripts/run-evals.mjs <plugin> --runs 3        # one plugin, three runs per case
node scripts/run-evals.mjs all --max-cost-usd 5     # every plugin, one run per case; the cap applies to each pass of each plugin (about $2.5 per plugin)
node scripts/summarize-evals.mjs                    # rewrite this page
```
